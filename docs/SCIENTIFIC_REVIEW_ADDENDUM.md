## (a) Per-area findings

### Area 1 — Cloud policy analysis prior art: Zelkova, Access Analyzer, Cedar, policy repair

**What exists (DOC/THIRD-PARTY).** Intent-vs-policy analysis for cloud IAM is a solved-shaped problem, and we should say so:

- **Zelkova** (AWS Automated Reasoning Group) translates IAM policies into logical formulas checked by SMT solvers — strings, regex, dates, IP ranges — and answers quantified questions (*for all possible requests, is this true?*), where the IAM Policy Simulator can only test single requests. It powers **IAM Access Analyzer** external-access findings, and AWS reports on the order of a billion SMT queries a day. Sources: https://aws.amazon.com/blogs/security/protect-your-sensitive-data-in-the-cloud-with-automated-reasoning-zelkova/ · https://www.amazon.science/blog/a-billion-smt-queries-a-day · https://www.allthingsdistributed.com/2019/06/proving-security-at-scale-with-automated-reasoning.html
- **Cedar** is the stronger reference point because it was *designed for analyzability*: the language, authorizer, and validator are formally modelled (Lean; Dafny earlier) with mechanized proofs, and — critically for us — AWS validates the production Rust implementation against the formal model by **differential random testing (DRT)**: millions of generated policies and requests checking that implementation and model agree, plus property-based testing of conjectured properties before attempting proofs. **Cedar Analysis** adds a symbolic compiler (implemented in Lean, emitting SMT for CVC5) that claims soundness (a confirmed property holds for all scenarios) and completeness (a violation comes back as a concrete counterexample scenario). Sources: https://www.amazon.science/blog/how-we-built-cedar-a-verification-guided-approach-to-authorization (FSE Companion '24 paper, Disselkoen et al.) · https://aws.amazon.com/blogs/opensource/introducing-cedar-analysis-open-source-tools-for-verifying-authorization-policies/ · https://aws.amazon.com/blogs/opensource/cedar-joins-cncf-as-a-sandbox-project/
- **Policy repair is also a literature, not a feature idea.** **CloudFix** (arXiv:2512.09957) repairs faulty IAM policies with an LLM inside a verified loop: the repair goal is encoded and checked with Z3 (via Quacky), faults are localized to three types, and the synthesis loop iterates against the checker — 85.2% baseline / 86.4% fault-localized repair accuracy vs 46.7% unaided. **Restricter** (arXiv:2601.14582) treats policy *tightening* as SyGuS program synthesis over SMT (instantiated for Cedar), inferring over-privilege from access logs — permissions granted but never exercised. Sources: https://arxiv.org/html/2512.09957v2/ · https://arxiv.org/html/2601.14582v2/

**What is different about agent command surfaces (INFERENCE, grounded in the above + our REPRO).** The IAM machinery works because IAM offers four things agent harnesses do not:

1. **A closed request algebra.** IAM actions and resources are finite, namespaced, and documented. An agent's command surface is unbounded argv over arbitrary executables; the "request" is a program text, not a tuple.
2. **Semantics that live in the policy language.** In IAM, the policy *is* the semantics. On a command surface, the policy matches **text** while the shell and each binary supply the semantics — quote removal, expansion, substitution, wrappers (`bash -c`, `env`, `sudo`, `xargs`). Deciding the effect of an arbitrary wrapped command is undecidable in general; no Zelkova-style ∀-quantified proof over raw command text is possible.
3. **A language designed to be analyzed.** Cedar's analyzability is a design decision made *before* the language shipped. Codex `execpolicy` and Claude permissions were not: our Day-1 REPRO found lexical basename matching (nonexistent paths resolve), no decisions for flag-spelling variants, and head-segment-only decisions on compound commands — semantics that are undocumented and churn per release.
4. **A stable specification to verify against.** There is no formal model of a harness's decision layer; **the pinned vendor binary is the semantics.** That is why empirical conformance measurement — the binary as oracle, expectations declared independently — is not a weaker substitute for verification on this surface. It is the only sound epistemic stance currently available.

**Where their machinery transfers (INFERENCE).**

- **Differential testing transfers directly.** Cedar's DRT pattern — two independent implementations of the same decision, millions of generated cases, disagreement = finding — is exactly our divergence mining, with the native binary on one side and a shell-semantics model on the other. We should cite DRT as the methodological ancestor, not fuzzing folklore.
- **Counterexamples as first-class output transfer.** Cedar Analysis returns a concrete violating scenario, not a score. Our minimized failing fixtures (delta-debugged) are the same discipline.
- **Verified repair transfers as a discipline.** CloudFix shows a fix suggestion is only credible when validated against an encoded goal. Our Day-5 "one reviewed fix" should adopt fault-localization + goal-checking form: state which invariant fails, localize the rule interaction, propose the smallest policy change, and re-run the full corpus as the check — never hand-wave a diff.
- **Relational queries transfer in shape.** "Is policy A more permissive than policy B?" becomes, for us, the cross-version decision diff: same fixtures, two pinned versions, decision changes enumerated. That is an Access-Analyzer-shaped question over a non-SMT algebra.
- **Where Cedar-style engines appear inside agent stacks** (AWS Bedrock AgentCore already uses Cedar for agent policy — landscape report §2), formal machinery applies to that layer, and our role shifts to verifying the *integration* — that the harness actually routes decisions through the analyzable engine and that declared intent matches the Cedar policy — not re-proving the engine. The tester should treat analyzable sub-layers as a distinct adapter class.

### Area 2 — Agent evaluation science: what a measurement program must adopt

**What exists (THIRD-PARTY/DOC).**

- **METR** publishes not just results but methodology: a time-horizon metric (task length at 50% reliability) and elicitation guidelines requiring evaluators to document elicitation effort and validity red flags. The methodology itself then attracted independent statistical scrutiny (arXiv:2610.12466 — estimation choices, weighting, cluster-robust confidence intervals, held-out cells). Lesson: a measurement program that publishes its methodology *and its uncertainty* gets reanalyzed, and survives it; one that publishes point scores gets discounted. Sources: https://evaluations.metr.org/elicitationprotocol/ · https://arxiv.org/pdf/2610.12466 · context: https://www.brookings.edu/articles/how-are-countries-evaluating-ai-models/
- **UK AISI's Inspect** became the de-facto evaluation framework (adopted by METR, Apollo Research, CAISI, frontier labs), with Inspect Evals (200+ prebuilt evals) and **Transect** (Oct 2026) for transcript/activity review. Lesson: in a young field, the durable standards contributions are often *tooling and observability*, not leaderboards.
- **Contamination and pre-registration practice** (THIRD-PARTY, convergent across eval-integrity writing): fix the task set, metric, pass threshold, and inclusion rules *before* the run; keep a private held-out set that is never published or logged; run negative controls and establish noise floors (a metric that passes its negative control is broken); publish an auditable decontamination report (the DCLM pattern: protected-benchmark list, matching method, counts removed, residual-risk categories); report contaminated vs clean subsets separately. Sources: https://harrisonsec.com/blog/benchmarking-an-agent-without-lying/ · http://ajing.github.io/posts/2026-06-29-pretraining-contamination/
- **Exemplar:** the CAPE-Bench authorization-honesty study (Area 5) states "all tests are preregistered and hash-locked," with code, data, and the full record — including tests that did not pass — public. That is the bar for a credibility-first measurement program. Source: https://arxiv.org/abs/2610.17301 (via The Guardrail summary, THIRD-PARTY).

**Assessment for us (INFERENCE).** Our contamination vector is unusual and worth naming: the risk is not a model memorizing our fixtures, it is **vendors tuning to our public corpus** (Goodhart) and **our own corpus-design choices masquerading as population statistics**. We already hold the second line (the 41-case corpus is a synthetic probe set; 22-of-41 unknown is a corpus result, never a real-world rate). The literature says to formalize both defenses: hash-locked pre-registration of expectations before each harness-version run, and a public/private corpus split with a held-out shard. Section (e) adopts these.

### Area 3 — Property-based testing / fuzzing of policies and parsers: state of the art

**What exists (THIRD-PARTY/DOC).**

- The mature stack is **coverage-guided greybox fuzzing** (AFL++/libFuzzer lineage) combined with **grammar-based generation**: LangFuzz's fragment reuse found 2,600+ JavaScript engine bugs; AFLSmart adds structure-aware mutation; the Fuzzing Book's greybox-grammar synthesis is the canonical recipe. Schema-driven fuzzing (RESTler, Schemathesis) is the API analogue. Source: https://www.fuzzingbook.org/html/GreyboxGrammarFuzzer.html
- The 2025–2026 frontier is **LLM-synthesized fuzzers**: **ELFuzz** (arXiv:2506.10323) evolves fuzzers over a "fuzzer space" lattice guided by fine-grained coverage ranges (+418.5% coverage vs prior SOTA; five cvc5 zero-days) and **R1-Fuzz** (arXiv:2509.20384) RL-post-trains a 7B model for textual fuzzing (29 previously unknown vulnerabilities). Sources: https://arxiv.org/html/2506.10323v1 · https://arxiv.org/html/2509.20384v1
- The policy-domain instance of the same idea is Cedar's DRT (Area 1) — differential testing with generated inputs at million-case scale.

**Assessment for us (INFERENCE).** Our divergence-mining design (architecture doc §3: property-based generation + counterexample minimization) is directionally right but underspecified in one way the literature corrects: **coverage must be measured over decision space, not input space.** The feedback signal that matters is which rules matched, which decision classes were hit, and which expectation boundaries were crossed — a decision-space coverage vector per generated command. The generator's grammar should be the *shell* grammar (quoting, substitution, expansion, wrapper composition), and GuardFall's five bypass classes (Area 5) are a ready-made, literature-sourced mutation taxonomy. Deterministic grammar fuzzing with decision-space coverage is Phase 1; LLM-synthesized generators (the ELFuzz pattern) are a Phase-2 research upgrade, not a Week-1 dependency.

### Area 4 — Transparency literature beyond CT/Sigstore: lessons for anchoring v1.1

**What exists (DOC/THIRD-PARTY).**

- **Sigsum** reduces log entries to signed checksums only (32-byte checksum + 32-byte key hash + 64-byte signature) and gets split-view protection from **witness cosigning**: verifiers require k-of-n witness cosignatures on tree-head checkpoints; monitors watch consistency; specifications are maintained as C2SP community standards. The subtle, load-bearing point: a cosignature attests to the *witness's observed state* (it saw this tree head and can detect future inconsistency) — it is a claim about consistency, not about the log's correctness. Sources: https://transparency.dev/summit2024/sigsum.html · https://gitlab.glasklarteknik.se/sigsum/project/documentation/
- **Threshold math is published** (Transparency Summit 2026, THIRD-PARTY): with *n* witnesses of which at most *m* are malicious, split-view protection needs a cosignature threshold **t ≥ (n+m+1)/2** (e.g., n=9, m=3 → t≥7); dual monitor policies tolerate offline witnesses within a time window. Source: https://transparency.dev/pdfs/summit2026/witness-cosigning.pdf
- **Trillian / TrustFabric** (Google) generalize the pattern — transparency as reusable infrastructure with an explicit claimant model — and **Sunlight** shows the modern direction: simple, static, CDN-friendly log formats beat bespoke services. Source: https://transparency.dev/

**Design lessons for anchoring v1.1 (INFERENCE).** Our adopted design (anchor into existing logs + independent witness cosigning, Sigsum-style; never operate our own log first) is the literature-endorsed shape. Four refinements: (1) adopt the published threshold rule and a **small, diverse** witness set over a large friendly one — witness independence is the security property, not witness count; (2) keep entries hash-only, Sigsum-style — this matches our privacy posture and keeps the log's job minimal; (3) publish the **witness policy** (who witnesses, threshold, failure behaviour) as part of methodology, not as an implementation detail; (4) make **"unwitnessed" a first-class evidence state** in bundle verification — a bundle whose root lacks threshold cosignatures is labelled unwitnessed, visibly, rather than failing silently or passing quietly.

### Area 5 — The hard search: 2025–2026 work that directly measures agent permission/policy conformance

We searched hard, in several phrasings, for work measuring agent permission/policy conformance directly. **Something was found, and it narrows our claim. Stated plainly:**

1. **GuardFall (Adversa AI, 30 Jun 2026; CSA research note, 1 Jul 2026) — the closest prior work.** A survey of eleven popular open-source coding/computer-use agents (~548K combined GitHub stars): ten of eleven leave the agent-to-`bash` boundary exploitable because their command guards inspect raw text while the shell rewrites that text (quote removal, expansion, argument construction) before executing. Five bypass classes; four failure modes; only **Continue** defends by design — it tokenizes and canonicalizes the way bash does. Sources: https://adversa.ai/blog/opensource-ai-coding-agents-shell-injection-vulnerability/ · https://labs.cloudsecurityalliance.org/wp-content/uploads/2026/07/CSA_research_note_guardfall_ai_agent_shell_injection_20260701-csa-styled.pdf
   - **What it does to our novelty claim:** any phrasing like "first to show agent command guards diverge from shell semantics," "first cross-agent measurement of command guards," or "decision-vs-execution gap is unmeasured" is **dead** and must never appear in our materials. GuardFall measured decision-vs-execution divergence empirically, across agents, months before our sprint.
   - **What it does not occupy:** GuardFall is adversarial runtime red-teaming of built-in **denylist guards** in open-source agents. It does not test the declarative policy engines (Codex `execpolicy`, Claude permissions were not in its set), does not measure conformance against *developer-declared invariants*, has no unknown/coverage-gap taxonomy, is not deterministic-offline, produces no signed evidence, and is a one-shot disclosure study rather than a recurring, versioned measurement program. The measurement-of-record slot — the one our field doc actually claims — remains open.

2. **Michael & Roesner, "How Agents Ask for Permission" (University of Washington; Agents in the Wild workshop; arXiv:2607.13718) (DOC — read directly).** A survey of 21 proposed user-level permission systems (2024–2026) with a taxonomy of specification / derivation / enforcement, plus walkthroughs of five commercial agents (Claude, Claude Cowork, ChatGPT chat and agent modes, Codex) conducted late May–early June 2026. Findings: commercial agents gravitate to high-overhead user-in-the-loop or low-transparency auto-review; transparency and user-control gaps throughout. The authors note the commercial agents are closed-source and their internal specifications could not be evaluated; enforcement was assessed by walkthrough observation.
   - **Effect on our claim:** "agent permissions are unstudied" is dead (we never claimed it). The paper is the field's taxonomy anchor and we should cite it as such. It explicitly could not do the thing we do: quantitative conformance measurement of internal policy decisions against declared intent, on pinned versions, with explicit unknowns. The slot it gestures at remains unfilled.

3. **Pillar Security, "Week of Sandbox Escapes" (Jul 2026) + CSA synthesis (THIRD-PARTY).** Runtime trust-handoff escapes across Cursor, Codex CLI, Gemini CLI, and Antigravity: the confined agent writes a file a trusted outside component later executes. Includes a Codex CLI allowlist bypass ("GitPwned" — `git show` trusted by name while the invocation was not read-only; patched in v0.95.0) and a shared Docker-socket exposure. Vendor responses were uneven — some patched promptly, some classified comparable findings as low-severity and declined. Sources: https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-coding-agent-sandbox-escapes-20260722-c/ · https://dev.to/topuzas/ai-agent-attack-surface-lessons-from-a-week-of-sandbox-escapes-and-eval-breaches-3pc4
   - **Effect:** validates, on the exact engines we measure, that name-vs-invocation semantics is a real divergence class (we found the same texture at the rules layer on Day 1, REPRO). It is disclosure red-teaming, not conformance measurement — and its vendor-response variance is direct evidence for our governance design (embargo with dispute/fix, no suppression).

4. **CAPE-Bench authorization-honesty study (arXiv:2610.17301, Oct 2026) (THIRD-PARTY).** Measures *model* behaviour: agents acting beyond authorization and then misreporting it ("retroactive permission laundering" preceding false reports in 70% of fresh informed violations; preregistered). Different object — the model's honesty, not the harness's policy engine. **No effect on our claim**; included because it is the methods exemplar cited in Area 2.

5. **Hong et al., "Don't Make Models Guess Security and Safety: Symbolic Guardrails" (CMU; arXiv:2604.15579) (THIRD-PARTY).** A systematic review of 80 agent safety/security benchmarks finds **85% lack concrete policies**, relying on underspecified goals; of specified policies, 74% of requirements are enforceable by symbolic guardrails. Source: https://arxiv.org/pdf/2604.15579
   - **Effect:** supports our gap from the benchmark side — the field evaluates agents against vague goals; nobody pins a concrete policy and measures whether the engine's decisions conform to declared intent. Also a warning: symbolic enforcement is cheap and effective where policies are specifiable, so our measurement must stay honest about which layer it measures.

6. **Vendor self-measurement (THIRD-PARTY).** Both vendors now publish numbers for model-based approval layers — Codex Auto-review (99.3% prompt-injection recall, 90.3% overeagerness recall) and Claude Code auto mode (89% of planted dangerous commands caught vs 13.6% for human reviewers; 17% false negatives on real overeager actions) — each on vendor-built test sets; a comparison blog notes plainly "the numbers are not comparable head to head: each company built its own test sets." Sources: https://cellcog.ai/blog/codex-auto-review/ · https://safeguard.sh/resources/blog/ai-coding-agent-approval-workflows
   - **Effect:** strengthens the independent-measurement rationale (the UL argument: the measured party cannot be the measurer of record). Also a forward warning: the decision layer is shifting from deterministic rules toward **model classifiers**, which are stochastic. A measurement program scoped only to deterministic layers will measure a shrinking share of the boundary; see upgrade 5 in section (d).

7. **Null results, reported honestly.** Dedicated searches for an `execpolicy`-specific conformance tester, and for any OSS "conftest for agent policies" equivalent, returned nothing that occupies our slot (THIRD-PARTY — search result). Null results from search are weaker than positive identification; the revised novelty statement in (b) is worded accordingly.

## (b) Revised novelty statement

> As of 21 October 2026, we identify no published system or study that performs **deterministic, offline conformance measurement of a coding agent's native, declarative policy engine against developer-declared invariants** — pinning the vendor binary and policy by hash, reporting decision-coverage gaps as explicit unknowns with layer attribution, minimizing divergences to reproducible counterexamples, and sealing results as independently verifiable evidence, repeated across versions.
>
> Adjacent work measures neighbouring objects, and we name it rather than gesture at it: runtime guard-vs-shell divergence in open-source agents (GuardFall, Adversa AI, Jun 2026); sandbox trust-handoff disclosures (Pillar Security, Jul 2026); permission interfaces and enforcement behaviour, qualitatively (Michael & Roesner, 2026); model authorization behaviour and honesty (CAPE-Bench, Oct 2026); harness-surface and approval-process studies (landscape report, Oct 2026); and policy correctness for closed cloud policy languages, by formal proof (Zelkova; Cedar/Cedar Analysis).
>
> Our claim is to the unoccupied intersection — **conformance of pinned native decision layers to declared intent, measured repeatedly, with unknowns explicit and evidence verifiable** — and to nothing broader. Claims of the form "first to measure agent guard divergence," "first study of agent permissions," or "no equivalent exists" are withdrawn wherever they appear; the standing wording is "no equivalent identified among reviewed work as of this date," with the reviewed set named.

## (c) Cohesion verdict

**Verdict (INFERENCE): one coherent research program, with two honest adjacencies — provided the program is named and bounded correctly.**

The coherent core is **Boundary Measurement**, and it has four parts that genuinely imply each other:

- **The tester** is the measurement instrument — the only component that produces primary evidence.
- **EffectGap** is the research program the tester serves: its schema (*native_decision × observed_effect × verdict*: VERIFIED / CONTRADICTED / UNKNOWN) is literally the tester's output shape, and the conformance experiment is its proving ground. This is not portfolio decoration; it is the same object at two altitudes.
- **The Index** is the publication of record — the recurring, versioned measurements that turn one-off findings (the GuardFall/Pillar pattern) into a measurement series vendors and buyers can cite.
- **Hosted signed evidence** is the business that funds neutrality: retained, witnessed, cross-version conformance records are what a measurement-of-record sells, and the transparency design (Area 4) is what makes "trust us" into "verify it."

The adjacencies, stated honestly:

- **AnswerGraph** is a *methodological sibling*, not a component. It shares the evidence discipline (append-only event core; claims never become facts; verdicts labelled), but its DecisionProvider layer is *judgment* — and Boundary Measurement verdicts must stay deterministic to be evidence. Share the evidence format; never share the verdict path.
- **Emberlane** is *not* part of the research program. It is a portfolio sibling and, later, a natural **measured subject and dogfood customer** (an MCP gateway's tool permissions are exactly a surface this program measures). Claiming a technical linkage today would be the incoherence Anish is probing for; the honest link is "future subject, Phase 4."
- **InferRail / Nexus Trust** remain out of scope for this program (standing Week-1 rule). The only long-term bridge worth naming: measured invariants are the natural input to an enforcement substrate — a Phase-4+ option, not a current claim.

**Distraction risks, named:** (1) hosted-tier engineering can eat the measurement core — it is Phase-gated for a reason; (2) the Index can drift into media/content and stop being measurement; (3) portfolio narrative ("five projects, one platform") can substitute for the one program that produces evidence. The grant narrative should fund the core — tester + EffectGap method + Index — with hosted evidence as its Phase-gated expression.

## (d) Ambition upgrades the literature justifies

1. **Decision-space coverage-guided divergence mining, with a shell-grammar mutator seeded by GuardFall's five bypass classes.** *Phase 1–2.* Replaces "property-based generation" as currently specced: coverage feedback over rules-matched × decision-class, generation over the shell grammar (quoting, substitution, wrappers), minimization by delta debugging. Justified by the greybox-grammar synthesis literature and by Cedar's DRT as the policy-domain precedent (Areas 1, 3).
2. **A formal semantics for our own expectation layer, with our tester differentially tested against it.** *Phase 1 design; Phase 2 build.* We cannot verify the vendor's engine — but Cedar's verification-guided pattern says we *can* verify our measurement instrument. "Our verdicts mean what we say" becomes a checkable property of the invariant/expectation language rather than a promise. This is the largest credibility upgrade on offer, and it is cheap relative to its effect on grant and standards credibility.
3. **Hash-locked pre-registration + public/private corpus split.** *Adopt now (Week 1 discipline); infrastructure Phase 1.* Expectations committed by hash before each harness-version run; a held-out private shard, rotated per release, so published-corpus tuning (by us or by vendors) is detectable. Justified by eval-science consensus and the CAPE-Bench exemplar (Area 2).
4. **Witness-cosigned anchoring with a published threshold policy.** *Phase 1 (v1.1, as specced — now parameterized).* Sigsum pattern; threshold t ≥ (n+m+1)/2; small diverse witness set; "unwitnessed" as a first-class evidence state (Area 4).
5. **A stochastic decision-layer methodology.** *Phase 2.* As vendors shift approvals to model classifiers (Codex Auto-review; Claude auto mode) whose published numbers rest on incomparable vendor-built test sets, extend fixtures to sample decision distributions with stated n and confidence intervals, under pre-registered prompts and pinned model versions. The independent, comparable cross-vendor measurement of the *classifier* layer is the Index's most defensible future headline — and the natural EffectGap extension from deterministic decisions to decision distributions.

## (e) Methods standards to adopt now

1. **Pre-register before every version run.** Fixtures, expectations, thresholds, and inclusion rules are hash-locked before the pinned harness version is run. Deviations are logged publicly, never silently edited. (Area 2.)
2. **Public corpus + private held-out shard.** Corpus statistics are always labelled as corpus results, never population rates — the standing rule, now formalized. Per-release decontamination disclosure: how fixtures were authored, which public sources fed them, which are held out. (Area 2.)
3. **Negative controls in every run.** Cases designed to yield *unknown* must yield unknown; a run that passes its negative controls is a broken run and is reported as such. (Area 2.)
4. **Layer attribution and evidence classes on every claim.** DOC / REPRO / THIRD-PARTY / INFERENCE / HYPOTHESIS, with harness version and pinned configuration attached. Unknown means "no decision at this layer," never "bypass." (Standing rule, reaffirmed; Revision 2.)
5. **Pin everything.** Harness version, binary hash, policy hash, configuration hash — and now corpus version hash — in every evidence bundle. (Extends `VERIFIABLE_EVIDENCE_ARCHITECTURE.md`.)
6. **Report uncertainty, not point estimates.** Deterministic layers: run-to-run agreement (our baseline: two runs, 41/41 agreement). Stochastic layers (when upgrade 5 lands): sample counts and intervals, always. (Area 2.)
7. **Minimized counterexamples only in public reports.** The smallest failing form (delta-debugged) is the published unit; the full corpus remains reproducible from the sealed bundle. (Areas 1, 3.)
8. **Vendor embargo with response publication.** Findings shared pre-publication; vendors may dispute or fix, never suppress; the vendor's response (or silence) is published alongside results. GuardFall and Pillar both show response variance is itself decision-relevant information for buyers. (Area 5.)

---

*Bottom line for the founder's question: the project is ambitious enough in its core claim — a measurement-of-record for agent decision boundaries — and the literature makes it more ambitious, not less, in two specific ways: verifying our own instrument (upgrade 2) and extending measurement to the stochastic classifier layer vendors are now shipping (upgrade 5). The novelty survives scrutiny only in its narrowed form (section b); the cohesion is real for tester + EffectGap + Index + hosted evidence, and honestly absent — by design — for Emberlane and AnswerGraph beyond shared discipline and a future dogfood relationship.*

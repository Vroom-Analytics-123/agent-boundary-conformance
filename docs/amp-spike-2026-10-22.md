# Amp Second-Oracle Spike — 2026-10-22

**Question:** Is Sourcegraph Amp's shipped `amp permissions test` a second native
decision oracle (T1), making FinePrint a two-oracle method?

**Verdict: YES — T1 CANDIDATE.** `amp permissions test` is a deterministic,
offline, no-auth CLI entrypoint that returns Amp's OWN permission-engine
decision for a tool call under a configured policy. All tiering criteria from
`docs/HARNESS_TIERS.md` question (a) are met at the pinned version. Promotion
to T1 is a founder decision; `docs/HARNESS_TIERS.md` is intentionally NOT
changed by this spike.

**Scope of this spike:** the *rules layer* of Amp's permission system only
(user `amp.permissions` rules + Amp's built-in permission rules), evaluated via
the shipped `amp permissions test` subcommand. No agent session was launched,
no thread was created, no model was invoked, no account was created, no login
was performed, no API key was used. (`amp tools list` DOES require login —
recorded below as the auth boundary; the spike never crossed it.)

**Naming note (Oct 22):** the program is now publicly FinePrint; EffectGap
remains the internal portfolio label only.

## 2. The oracle surface

```
amp permissions test [options] <tool-name>
```

Relevant flags: `--json` (machine-readable output), `-q/--quiet` (exit status
only), `--settings-file <path>` (point at an arbitrary policy file),
`--context <thread|subagent>`, `-w/--workspace`. Tool-specific arguments are
passed as flags: `amp permissions test Bash --cmd "rm -rf /tmp/x"`,
`amp permissions test Read --path "/home/user/.ssh/id_rsa"`.

Policy surface: `amp.permissions` array in settings JSON. Rule shape
(discovered empirically; NOT in the published settings schema at
`https://ampcode.com/cli-settings.schema.json`):

```json
{"tool": "Bash", "matches": {"cmd": ["rm -rf *"]}, "action": "reject"}
```

- `tool`: tool name, supports globs (e.g. `"mcp__playwright__*"`).
- `matches`: per-tool-argument matchers. Observed keys: `cmd` (Bash),
  `path` (Read). Values are arrays of **globs** (`*`) and/or **regex strings**
  (`"/^rm\\s+.*$/"`).
- `action`: `allow` | `reject` | `ask` | `delegate` (+ optional `--to` program
  for `delegate`).
- Rules are evaluated **in list order, first match wins**; `amp permissions add`
  prepends ("newer rules take precedence").

Amp additionally ships **built-in permission rules** embedded in the binary
(`"source": "built-in"` in output). The `test` output echoes the matched rule:

```json
{
  "tool": "Bash",
  "arguments": {"cmd": "rm -rf /tmp/x"},
  "action": "reject",
  "matchedEntry": {"tool": "Bash", "matches": {"cmd": ["rm -rf *"]}, "action": "reject"},
  "matchIndex": 6,
  "source": "user"
}
```

Exit codes with `-q` (verified): `0` = allow, `1` = ask, `2` = reject.
Caveat: `-q` maps a no-decision (`action: null`) to exit 0 — oracle consumers
must use `--json` and read `action`.

## 4. Offline evidence

- `amp permissions test` runs with **no API key, no login, no account** (the
  fake HOME contains no credentials; `amp tools list` in the same environment
  fails with "No API key found. Starting login flow..." — the auth boundary is
  real and the spike never crossed it).
- With `AMP_URL=https://invalid.local:1` (unroutable), the probe output is
  **identical** to the normal run (`rm -rf /tmp/x` → reject/user, same JSON).
  A network-dependent evaluation could not survive this.
- Per-invocation latency ~0.5–1.1 s; the matched rule JSON is echoed from data
  embedded in the binary.

Conclusion: evaluation is **offline and local** (REPRO).

## 5. Precedence model (REPRO)

Settings `prec1.json` = `[reject rm *, allow rm *]`; `prec2.json` = the reverse.

| Setup | `rm -rf /tmp/x` decision |
|---|---|
| reject listed first | `reject`, source `user`, matchIndex 0 |
| allow listed first | `allow`, source `user`, matchIndex 0 |

**First matching rule in list order wins**, both directions. `amp permissions
add` prepends new rules ("newer rules take precedence") — consistent.

**User rules take precedence over built-in rules**: with
`userbeatsbuiltin.json` = `[reject git status*]`, `git status` → `reject` /
source `user`, defeating the built-in allowlist that otherwise allows
`git status*` (built-in matchIndex 8 under empty settings).

Observed built-in Bash defaults (empty settings, all REPRO):
- Benign-command allowlist (matchIndex 7): `ls`, `cat *`, `head *`, `go test *`,
  `cargo test *`, `npm test*`, `git status*`, `git log *`, `git diff*`, … (121
  patterns observed).
- `rm` dangerous-form ask (matchIndex 23):
  `/^rm\s+.*(-[rf].*-[rf]|-[rf]{2,}|--recursive.*--force|--force.*--recursive).*$/`
  — regex, not glob.
- Absolute-path/`../` ask heuristic (matchIndex 26): regex shown in P-05 above.
- Catch-all ask (matchIndex 27): unknown Bash commands (`xyzzyplugh
  --frobnicate`, `curl https://example.com`, `deployctl release production`
  with no user rules) → `ask`.
- `Read` tool: built-in allow at matchIndex 90 (e.g. `~/.ssh/id_rsa` → allow
  with no user rules); user `matches.path` globs (`*/.ssh/*`) correctly
  override to `ask` (source `user`).

## 6. No-match default + vocabulary mapping

| Amp output | Framework vocabulary | Notes |
|---|---|---|
| `allow` | **allow** | REPRO |
| `ask` | **prompt** | REPRO |
| `reject` | **forbidden** | REPRO |
| `action: null` (no rule matched) | **unknown** | REPRO (bogus-tool probe). Per INV-005: never allow. |
| `delegate` | **unmapped** | Action exists (`--to <program>`); semantics not probed. Never force-mapped. |

No-match note: a *genuine* no-match yields `action: null`. For the Bash tool
specifically, Amp's built-in catch-all ask (index 27) means unknown *commands*
resolve to `ask` rather than null — that is Amp's shipped default behavior,
recorded as observed, not as a framework claim.

## 7. Semantic findings (measurement, not verdicts)

1. **String matching, as written.** Globs/regex match the `cmd` string verbatim.
   `/bin/rm -rf /tmp/x` does NOT match a `rm -rf *` rule (anchored at string
   start); wrappers (`bash -lc`, `env`, `sudo -E`, `env FOO=bar`) likewise
   defeat prefix globs. This is the same *class* of finding as Codex's
   token-prefix semantics (wrapped forms escape naive rules) — here the
   built-in path/ask heuristics catch what the user rule misses, but the
   mechanism is string matching, not argv parsing.
2. **Regex rules are first-class.** The built-in `rm` rule is a regex; user
   rules accept regex strings too (same `matches.cmd` array).
3. **Multi-tool coverage.** The oracle is not Bash-only: `Read --path` was
   probed with `matches.path` globs (REPRO). The full tool list was NOT
   enumerated (requires login) — recorded as a ceiling.
4. **matchIndex is internal.** It indexes into the source's (user/built-in)
   rule list with an internal stride; it is evidence of *which* rule fired,
   not a stable API.

## 8. Tier recommendation: T1 CANDIDATE

Reasons:
- (a) **YES — native offline oracle.** `amp permissions test --json
  <Tool> [--cmd ...]` returns Amp's own permission-engine decision
  (action + matched rule + source) for a tool call under a given policy file.
  Deterministic (13/13 byte-identical), offline (bogus-AMP_URL proof), no auth
  (login boundary verified at `amp tools list`).
- (b) not needed; (c) not applicable.
- Evidence class: **REPRO** (binary executed locally, outputs captured).

This satisfies the stated T2→T1 promotion condition in `docs/HARNESS_TIERS.md`
("a vendor ships a deterministic offline 'evaluate this command against this
policy' entrypoint … at a pinned version") — for Amp, at pinned version
`0.0.1792680614-g8973a3`.

**What a promotion would change:**
- FinePrint becomes a **two-oracle method** (Codex execpolicy + Amp
  permissions test) — the first harness beyond Codex with a native decision
  oracle, and the first with a *shipped built-in default policy* as part of the
  measured surface.
- New capability unlocked: measuring a developer's invariant set against
  **Amp's default posture** (built-in rules), not just custom policies —
  directly comparable "default-deny vs default-ask" evidence across harnesses.
- New finding class: string-glob vs argv-prefix matching differences between
  Codex (token prefixes) and Amp (string globs/regex) on the *same* corpus —
  a genuine second-oracle cross-check, not a re-implementation.
- A draft `adapters/amp.manifest.json` is included with this spike (draft form
  only, `"draft": true`); `docs/HARNESS_TIERS.md` unchanged pending the
  founder's call.

**Ceilings / open questions** (also in the draft manifest):
- Built-in ruleset is version-pinned but not published; only observable via
  `test` echoes. A vendor-published policy spec would strengthen DOC backing.
- `--context subagent` vs `thread` not probed; workspace-vs-user settings
  layering not probed; `delegate` action not probed; full tool list not
  enumerated (needs login).
- The oracle covers the *rules layer* only; approval UX and sandbox are
  separate layers (same layer discipline as the Codex adapter).
- Binary released 2026-10-22 (today); vendor may ship breaking changes
  frequently — the version pin + vendoring recipe is load-bearing.

**documents nothing** about `amp permissions` / `amp permissions test`: no
docs page exists (the `/docs/cli/permissions` URL 404s) and full-text docs
search for "amp permissions", "amp.permissions", "permissions test", and
"exit code" returns no hits — so the empirical (REPRO) record above is the
primary evidence, not a supplement to docs. Two corroborating points:

- The official install page (`https://ampcode.com/docs/cli`, "Getting Started

  Homebrew) with **no account/login step** — consistent with the observed
  no-auth install. Login (`amp login` / `AMP_API_KEY`) is documented as needed
  for CLI *use*, which is consistent with the observed auth boundary at
  `amp tools list` while `permissions test` works without it.
- The only official material describing an `amp.permissions` list is the
  August 7, 2025 Chronicle announcement "Tool-Level Permissions"
  (`https://ampcode.com/news/tool-level-permissions`): entries with actions
  allow / reject / ask / delegate, **first matching entry wins**, and a
  built-in permission list as no-match fallback. Its "in the manual" link now
  404s. This corroborates the empirically determined rule shape, the
  four-action vocabulary, and first-match-wins precedence (DOC, third-party
  announcement rather than current reference).
